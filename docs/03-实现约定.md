## 1. 砍预算规则（定死）

自动砍/降级**只比较**：

```
已占用一次性花费  vs  一次性预算
```

**已占用** = 搬家运输 ¥2,000 + 清运费 + 搬运加价 + 过渡住宿（¥400 × 晚数）+ 仍为「计划中 / 已降级」的置办金额。

**预计回款只记在账本上，不参与自动砍级。** 转卖沙发的 ¥800 不得把「已占用」变小，也不得抬高用于判断砍级的预算。

因此路演「先把沙发标成转卖，再把一次性预算改到 6000」时：

| 项 | 值 |
|---|---|
| 已占用（默认置办未砍、无清运/过渡） | ¥6,300（2,000 + 4,300） |
| 一次性预算 | ¥6,000 |
| 预计回款（沙发转卖） | ¥800（账本里有，未到账） |
| 自动结果 | 已占用 6,300 > 6,000 → 按 01 第 4.4 节先砍灯饰装饰 ¥400 → 已占用 ¥5,900 |

禁止的错误实现：用「可置办额度 = 预算 − 搬家 − 清运 − 过渡 + 回款」去决定是否还要砍，导致 6,000 + 回款 800 看起来仍够置办、置办完全不动。

手动勾选砍掉/降级仍可用。自动流程只在「已占用 > 一次性预算」时按优先级继续砍/降级，**不会因为回款或结余而把已砍项自动加回**。

缺口/结余 = 一次性预算 − 已占用（同样不减回款）。看板上不单独铺三张账本卡；金额出现在置办行、房源月租和重算后的要求原文里。

## 5. 模型

模型地址、模型名和 Key 写在 `js/ai.js`，页面上没有填写入口。浏览器只请求同源 `/api/chat`。

本地预览：仓库根目录执行 `python3 server.py`（或 `npm start`），打开 `http://127.0.0.1:8766/`。`server.py` 提供静态页，并把 `/api/chat` 转发到 DeepSeek。

模型实际被调用的两处：

- **生成计划**：用户自己点「生成计划」，或在看板上「编辑」后保存（且当前不是 Demo 剧本）。失败则按原句本地拆一版。
- **写转卖帖**：旧物标成转卖后点「生成转卖帖」。失败用第 4 节文案。

「Demo试运行」不调用模型。筛房、算钱、砍置办、过渡住宿只用本节与 01 的规则。照片不上传给模型。
