# 搬伴 · 功能设计文档（Demo）

> 范围：纯前端 Demo 的功能层。不含视觉规范、组件样式、动效。  
> 依据：作品申报文案。实现以当前看板为准。  
> 关联：`docs/00-作品申报文案.md`、`docs/02-视觉设计文档.md`、`docs/03-实现约定.md`

---

## 1. 文档目的与成功标准

本 Demo 要让路演在几分钟内看见下面这条可点路径：

1. **一句话摊开计划**。旧房、新房先留白，日程先出现。
2. **拍照或用示例房间**后，旧物逐件给出转卖、丢弃或带走；转卖可预览并复制小红书帖，不真发。
3. **点「选一套」**按通勤列出房源，点进详情后写回计划。
4. **点「置办家具」**补上新家要买的东西。月租不进一次性预算。
5. **编辑原句**后，日期、花费和筛房条件一起重算。

「Demo试运行」不依赖模型。自己点「生成计划」时，模型可用就填计划；失败则按原句本地拆一版，看板结构不变。

## 2. 产品定义

### 2.1 一句话

用户用一句话说清跨城搬家约束。搬伴先摊开同一块看板：旧房和新房缺什么就留白，补上之后计划才长出来。改要求后，时间和一次性花费跟着变。

### 2.2 主交互

- **看板为主场**。启动页负责说清一句约束，也可以直接走 Demo。
- 出帖、房源详情从右侧拉出。选房列表和置办清单长在右轨里，不另开主页。
- 启动页顶栏是「产品说明」。看板上改要求用「编辑」，不是一条单独的追加输入。

### 2.3 明确不做（本 Demo）

| 不做 | 原因 |
|---|---|
| 登录、云端存档 | 纯前端，刷新即丢失 |
| 真地图 / 真房源 API | 通勤分钟数写在 mock 房源上 |
| 真发小红书 | 出帖只到预览和复制 |
| 把照片交给模型识别 | 上传或示例图只播扫描动画，旧物来自计划 |
| 切换公司地点 | 公司写死陆家嘴，只调通勤上限 |
| 逐条撤销约束 | 只提供「重置 Demo」，回到启动页 |
| 通用求解器 / 选购商城 | 砍预算只按固定优先级 |

```
启动页
  ├─ 一句约束（可语音，Chrome）
  ├─ Demo试运行 / 生成计划
  └─ 产品说明（右侧栏）
        ↓

  ├─ 左轨：旧房（先留白 → 照片 → 旧物）

```

第一次打开会有分步引导。走完或跳过后不再自动出现。「Demo试运行」按引导带完认旧物、选房和置办。

## 4. 剧本设定与 Mock 数据

故事时间与真实日历解耦。Demo 路径的数字包如下；自己生成计划时，旧物和置办按原句变化，不锁死这一套名字。

### 4.1 故事

北京租约到期，人去上海入职，需要同时处理退租、旧物去留、在上海租到能通勤的房子、买齐必要家具。一次性预算紧，月租另算。

### 4.2 固定数字包（Demo）

| 项 | 值 |
|---|---|
| 北京退租日 | 6/30 |
| 上海报到日 | 7/15 |
| 公司地点 | 陆家嘴（不可改） |
| 默认通勤上限 | ≤45 分钟 |
| 一次性总预算 | ¥8,000 |
| 搬家运输 | ¥2,000（默认占用） |
| 过渡住宿 | 必要时 ¥400/晚 × 缺口晚数 |

**账本分列：**

- **一次性花费**：搬家、清运、过渡、置办。受预算约束。砍预算只砍这一列。
- **月租金**：随选中房源变化，只展示在房源卡上，不计入 8,000。

### 4.3 旧物（左轨，Demo）

| ID | 名称 | 预计回款（转卖） | 清运费（丢弃） | 搬运加价（带走） |
|---|---|---|---|---|
| item-sofa | 沙发 | ¥800 | — | ¥300 |
| item-table | 桌椅 | ¥200 | — | ¥100 |
| item-mattress | 床垫 | —（不建议转卖） | ¥150 | ¥100 |

床垫仍允许选「转卖」（会出帖），预计回款为 ¥0。回款不减少已占用，也不参与砍级。

生成自己的计划时，旧物 2 到 4 件，名称来自原句或按场景推断。未点名时不要固定输出沙发、桌椅、床垫。

### 4.4 置办（右轨，砍预算优先级从上到下）

| 优先级（先砍/先降级） | ID | 名称 | 计划中 | 已降级 |
|---|---|---|---|---|
| 1 | buy-decor | 灯饰装饰 | ¥400 | 砍掉（¥0） |
| 2 | buy-table | 桌椅 | ¥600 | 砍掉（¥0） |
| 3 | buy-sofa | 新沙发 | ¥1,800 | ¥900 |
| 4 | buy-bed | 床 | ¥1,500 | 不降级，只砍掉 |

预算收紧时按此顺序自动处理：先砍装饰，再砍桌椅，再降级新沙发，仍超则砍新沙发，再超则砍床。自己生成的置办沿用同一规则：有更低价才降级，否则直接砍掉。

置办默认不展示。选定新房后点「置办家具」才列出。

### 4.5 房源

六套，机器可读数据在 `data/listings.json`，矩阵见 `docs/03-实现约定.md`。前端按「通勤 ≤ 当前上限」且「若有宠物约束则必须允许宠物」过滤。

路演默认点 `lz-minsheng`：通勤合格、不允许宠物、起租能覆盖 6/30。要求改成必须能养猫后，这套会被清空。

## 5. 核心对象与状态

### 5.1 计划（Plan）

一份计划 = 约束 + 账本 + 左轨 + 右轨 + 月历日期。旧物和置办可以先算好，但左轨要等照片，右轨的置办要等用户点开。

### 5.2 约束

开场一句写入 `kind = initial`。句中若出现猫、狗、宠物、养猫，另记一条 `kind = pet`。

看板上改要求是**整句替换**后再生成，不是在后面追加一条。Demo 剧本按原句本地拆；自己生成的计划走模型，失败再本地拆。同名旧物的去留、同名置办的状态会尽量保留。已选房若不再符合通勤或宠物条件，清空并提示重新选房。

### 5.3 旧物状态

```
待处理 → 转卖 | 丢弃 | 带走
```

三选一。再点已选项回到待处理。

- 仅转卖可打开出帖。出帖不改变该状态。
- 丢弃：一次性花费加上清运费。
- 带走：一次性花费加上搬运加价。
- 转卖：预计回款只展示（未到账），不减已占用。

左轨在没有照片时不列出旧物。点「用示例房间」或上传图片后，播放约 1.3 秒扫描，再列出计划里的旧物。

### 5.4 新房状态

```
待选 → 选择中（右轨列出过滤后的房源）→ 已选
已选 + 不满足现行过滤条件 → 待选（清空）
```

点某一套会写入计划，并打开房源详情。「就这套」关闭详情。已选后可以「换一套」。

### 5.5 置办项状态

```
计划中 | 已降级 | 已砍掉
```

用户可手动砍掉；该行有更低价时可以手动降级。预算变紧时也会自动改这些状态。

### 5.6 月历

| 标记 | 含义 |
|---|---|
| 北京退租 | 计划中的退租日 |
| 上海起租 | 已选房源的可起租日；未选则不标 |
| 过渡住宿 | 仅当起租无法覆盖退租时插入 |
| 上海报到 | 计划中的报到日 |

左右箭头按月翻。未选房时不自动加过渡费，退租日可标空窗风险。

### 5.7 共享账本

**一次性**

- 已占用 = 搬家运输 + 清运 + 搬运加价 + 过渡 + 仍为「计划中 / 已降级」的置办
- 预计回款 = 状态为转卖的旧物回款之和
- 自动砍级只看「已占用 > 一次性预算」。回款不参与。
- 缺口/结余 = 一次性预算 − 已占用

**月租**：已选房源的月租金，写在房源卡上。

## 6. 写死的两条依赖

### 依赖① 资金

沙发是否转卖只影响预计回款的展示。砍置办始终按第 4.4 节优先级，不把回款算进可花的钱。

### 依赖② 时间：起租必须覆盖退租

- 已选房源的可起租日 ≤ 退租日：不插入过渡。
- 否则：晚数 = 起租日 − 退租日，一次性花费加上 ¥400 × 晚数，月历标出过渡。
- 未选房：不加过渡费。

## 7. 功能规格

### 7.1 启动页

输入框默认为空，占位「输入你的需求」。麦克风把语音写进这句话（需 Chrome）。

- **Demo试运行**：填入第 4 节默认句，用内置剧本进入看板，并继续引导。
- **生成计划**：把这句话交给模型填计划。无内容时提示先写一句。失败时本地拆句，并提示「这次按原句本地拆了一版」。

生成过程中主按钮变为「生成中」，并依次显示：正在读原句、划出日期预算和待办、给旧物定价并配置办。

### 7.2 看板

同时可见：

- 你的要求，关键词划线
- 左轨旧房、右轨新房
- 月历
- 重置 Demo

左轨空态：「上传房屋照片」「用示例房间」。  
右轨空态：「选一套」。选定后空态变为「置办家具」，点开才列出清单。

编辑要求：点「编辑」，改完整句，点「保存」。Demo 路径本地重算；自己生成的路径再调模型。

### 7.3 出帖

1. 仅转卖状态可进入。
2. 预览用该物图片，侧栏是一张笔记卡。
3. 模型写标题、正文、标签。失败用 `data/post-fallbacks.json`。
4. 「复制文案」复制标题、正文和标签。
5. 关闭后状态仍是转卖。

### 7.4 筛房

主路径在右轨：点「选一套」，列出当前通勤和宠物条件下的房源。

侧栏「按通勤筛房」仍可把上限改成 30 / 45 / 60 分钟。无结果时提示放宽通勤。有宠物约束时不能单删这一条，只能重置。

点选一套后写入月租、起租、通勤。若因此加上过渡或砍了置办，规则照跑；看板上用房源卡、置办金额和月历体现，不另弹一张「计划已改写」卡。

### 7.5 重置

「重置 Demo」清空计划、照片和编辑态，回到启动页。刷新浏览器同样回到启动页。

## 8. 路演路径

1. 启动页点「Demo试运行」，或自己写一句后点「生成计划」。
2. 看板上旧房、新房留白。点「用示例房间」（或上传照片），等扫描结束，看到沙发、桌椅、床垫。
3. 沙发选「转卖」，生成转卖帖，复制后关闭。
4. 点「选一套」，点民生路那套，在详情里看月租、位置、通勤、起租、宠物，点「就这套」。
5. 点「置办家具」。月租不进 8000。
6. 点「编辑」，把预算改到 6000，或加上「必须能养猫」。日期、花费和已选房按规则更新。
7. 需要时「重置 Demo」。

## 9. AI 如何接入

### 9.1 原则

- 房源、Demo 旧物、价格、通勤分钟全部在前端数据里。
- 模型做两件用户能点到的事：**按原句填计划**、**写转卖帖**。
- 筛房、加减钱、砍置办、过渡晚数用确定性规则。
- 请求发到同源 `/api/chat`，由 `server.py` 转发。页面不提供 Key 输入框。
- 模型失败时看板仍可走完。

### 9.2 调用

| 调用 | 何时 | 失败回退 |
|---|---|---|
| 填计划 | 「生成计划」，或非 Demo 时「编辑」后保存 | 按原句本地拆一版 |
| 写帖 | 转卖后「生成转卖帖」 | 该物品固定文案 |

Demo试运行、扫描照片、筛房、算账、砍置办、插过渡：**不调用模型**。

### 9.3 产品说明里要讲清的边界

启动页「产品说明」写给路演看，不必再做页脚全文。讲解时对准这几条：

- 模型读原句，划出日期、地点、预算和待办，并填写旧物与置办。
- 模型写转卖帖。复制不会真发出去。
- 照片是给用户看的扫描过程，物品名单来自计划，不是视觉模型看图的结果。
- 筛房、算钱、砍置办、过渡住宿是规则。
